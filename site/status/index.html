  • 4–8 authenticated EUDs per node

    Operations · Unverified

    CONOPS §6. One MULE supports one field team. The count is a planning case.

    §6 and success criterion 2 defer the maximum to Stage 2. Do not quote it as capacity.

  • Lose capacity in a fixed order

    Design · Simulated

    CONOPS §5.5: high-throughput IP, then range-oriented IP, then LoRa, then local digital, then analog/manual PACE. mule/modes.py encodes the middle of that as NOMINAL-IP, DEGRADED-IP, LOW-BANDWIDTH, and ISOLATED.

    Exercised against fakes. Association is not capability: a fresh batman-adv mesh can be linked and still carry nothing for tens of seconds. Not a radio trace.

  • Access point and high-throughput mesh are different functions

    Design · Unverified

    FML-ADR-045, a planning baseline. Phones join wifi_ap. wifi_mesh is the inter-node rung. The access point cannot raise that rung.

    TBR-RF-03 is open. Separate radios are the planning assumption until concurrency is proven.

  • HaLow is the range-oriented IP bearer

    Design · Unverified

    CONOPS §34. Expected traffic is ATAK, PLI, GeoChat, CoT, moderate files, administrative traffic, and approved field services. FML-ADR-080 names this rung VOICE: audio and PTT over IP, not video. A ceiling, not a measurement. No HaLow module is selected.

    FML-ADR-062 requires a mesh-capable mac80211 interface and refuses to pick a vendor. TBR-RF-01 and TBR-LINUX-01 are open.

  • LoRa stays a non-IP plane

    Software · Simulated

    CONOPS §35. TBR-NET-02 is closed on FML-ADR-070: Contact.callsign and GeoChat.to are the identity fields. test/bench/geochat-survival.sh carries them across two meshtasticd nodes.

    That run is simulated. It is not a range test, and LoRa still shall not carry arbitrary IP.

  • HaLow and LoRa on independent chains

    Hardware · Unverified

    CONOPS §36. Separate RF chains and antennas. When IP is down, keeping LoRa usable outranks aggressive HaLow reacquisition.

    Unrestricted simultaneous transmit is not a requirement. TBR-RF-02 has no hardware result.

  • Local MBTiles, served as z/x/y

    Software · Simulated

    FML-ADR-073. TBR-MAP-01 records a real iTAK client rendering a map from the node with WAN cut, and a mesh fallback whose hop is mac80211_hwsim. Martin is the selected server.

    The trade is still open. No CM4 footprint, no permitted-source imagery pack, and no measurement that local tiles spare RF.

  • Peer ATAK without a TAK server

    Software · Unverified

    CONOPS §50.4 and §9.2. If the shared server is gone, peer situational awareness on the node continues. OpenTAKServer is the preferred server (FML-ADR-032), not a proven one.

    No hardware-verified ATAK, WinTAK, or iTAK mission session on a MULE radio. The iTAK evidence so far is the map interface.

  • Voice is not a MULE service

    Design · Unverified

    CONOPS §32. The node does not by itself satisfy a voice requirement. Analog and manual PACE stay outside it.

    FML-ADR-064 through 067 select a DM-32UV plus audio/PTT-over-IP direction. Those trades are open, and BOM v0.4 is received input, not a baseline.

  • WAN is optional. Authorized MULEs may use the overlay

    Design · Unverified

    CONOPS §41–§43. Any standard MULE can be the one active local gateway. Authorized MULEs may use the WAN overlay for approved inter-MULE traffic. That overlay does not extend the RF mesh. An EUD does not join it unless the mission selects assigned-MULE-only, and then only as far as its assigned MULE. Loss of WAN leaves local access, the mesh, peer ATAK, S0/S1, and LoRa.

    FML-ADR-069, pooled gateways, is a target. TBR-NET-04 is open and unowned. v1 does not run competing automatic gateways.

  • Admission and trust are specified as targets

    Design · Unverified

    EAP-TLS is the production admission target (FML-ADR-038). step-ca is the preferred PKI (FML-ADR-036). Mission Trust is approved original software and is not a CA (FML-ADR-047).

    None of that is built. TBR-ID-01, the browser identity provider, is open.

  • 802.11s and batman-adv in BATMAN-IV

    Software · Simulated

    FML-ADR-053. The IV-versus-V choice is a planning baseline. An 802.11s mesh with BATMAN-IV has been exercised on mac80211_hwsim, with no radio.

    FML-ADR-024 (BATMAN-V) is superseded. The hwsim notes do not close TBR-LINUX-01.

  • Prototype and test BOM, rev A

    Hardware · Unverified

    hardware/prototype/prototype-bom-revA.csv is pinned. It answers what to buy to make the architecture decisions. Two field nodes, one bench-powered HaLow relay, shared instruments.

    Not a production baseline. No block is qualified. Battery is held. Power figures in the notes are estimates superseded by TBR-PWR-01.

  • The digital twin is software

    Software · Simulated

    The digital twin is test/flatsat. It runs the node logic with radio, power, thermal, and time replaced by fakes. That is a real software result.

    No device has been assembled or booted. A bench photograph is not this digital twin.

  • No enclosure, antenna, or compute module is selected

    Hardware · Unverified

    CONOPS §38: external antennas are field-replaceable spares, swapped without opening the core. The prototype notes discuss a taller extrusion and an internal GNSS patch behind a non-metallic end.

    That patch attenuation is untested. A pouch, a top-deck GPS puck, and an antenna count are not decisions.

  • Canyon story of CONOPS §77

    Operations · Unverified

    Three teams, Alpha, Bravo, and Charlie, each with one MULE. The ridge team is the HaLow geometry between the floor and the trailhead. Placement is an illustration.

    Not a propagation study, not Stage 2, and not a relay product. The bench relay in the test BOM is a third article so multi-hop can be measured later.

  • Production hardware

    Hardware · Unverified

    Pre-PDR. Nothing in the repository is hardware-verified. No image has been built.

    There is no production MULE to buy, flash, or field.

The repository

Design record, node logic, and evidence packets live in homelab-net/FML-MULE. Start with SAFETY.md and REGULATORY.md, then the CONOPS, then STATUS.md. STATUS.md is generated. Do not treat a paragraph on this website as newer than that file.

Sub-GHz hardware discussed for 902–928 MHz is not usable in the EU or the UK. The drawings on this site are illustrations. They are not a mechanical baseline.
