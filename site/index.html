Open · Local-first · Team infrastructure

Bring the network.
Bring the services.

MULE is an open-source team node for volunteer response, training, and field experiments. Several radio functions share one local computer, so a team still has maps, files, and TAK-compatible services when the wider network is gone.

Graceful degradation

Lose capacity, not the environment.

CONOPS §5.5. The objective is the highest-priority capability still available, not every service under every condition.

  1. 01High-throughput IPVideo, large files, bulk sync. The wifi_mesh rung.
  2. 02Range-oriented IPHaLow. TAK, maps, voice-class IP, moderate imagery, browser services. Not HD video.
  3. 03LoRa / MeshtasticPLI, short text, status, alerts. Not an IP path.
  4. 04Local digitalCached maps, files, and peer ATAK on this node.
  5. 05Analog / manual PACEOutside the node. Includes voice.

On the node, the code names the rungs NOMINAL-IP, DEGRADED-IP, LOW-BANDWIDTH, and ISOLATED. DEGRADED-IP is the VOICE tier in FML-ADR-080: audio and PTT over IP, not HD video, and only a ceiling. The analog voice plan stays outside the node. EUD access point is required and is not one of those rungs. None of this is hardware-verified.

Walk the canyon

What is not decided

A closed box and a spare antenna. Not a radio product.

No compute module, enclosure, battery, or antenna is selected. External antennas are field-replaceable spares, and HaLow and LoRa need independent chains. An internal GNSS patch behind a non-metallic end is a prototype note, untested, not a puck on the lid.

The working picture is three teams, not one hero radio. Architecture walks the canyon as a CONOPS §77 deployment.

Operational value first

One team. One local environment.

No cellular service, and no WAN, is required for the work that lives on the node.

Planning case, not a measured maximum: 4–8 authenticated end-user devices per MULE. CONOPS §6.

  • Cached maps and local files
  • Peer ATAK on this node
  • Ordinary TAK when an IP path exists
  • PLI, text, and alerts on LoRa
  • Optional WAN through one MULE gateway
  • Analog and manual PACE outside the node

The radio isn’t the point

A link moves packets. MULE brings infrastructure.

MULE reuses existing RF, mesh, and TAK technologies. The engineering problem is integrating communications, compute, storage, identity, local services, and replaceable hardware on one host.

  1. 01

    Several radio functions

    An access point for phones, a high-throughput mesh between nodes, HaLow for range, and LoRa as a non-IP plane. Ethernet is a practical wired path. They are not one pipe with a volume knob.

  2. 02

    Edge compute and data

    Cached maps, files, and local mission services stay on the node. The scarce thing is RF. The node should not spend it fetching the same map again.

  3. 03

    Team services

    Peer ATAK, a preferred TAK server when a host is reachable, files, and status share one Debian host. The link moves packets. The services are why the link exists.

Built and proved in the open

Open architecture. Inspectable evidence.

The repository says what it knows, what it has simulated, and what still needs a radio. Nothing is hardware-verified. There is no production MULE.

  1. 01UnverifiedA decision or a requirement, with no packet a stranger can check.
  2. 02SimulatedNode logic, or a bench script, against fakes or a software radio. Not RF.
  3. 03Hardware-verifiedA named article, a procedure, and a log. This rung is empty.
