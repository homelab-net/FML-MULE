# Test data

Fixed inputs for unit tests that would otherwise need a library or a radio CI
does not have. Every string here is synthetic.

## `unishox2_vectors.json`

Unishox2 compressed strings and their originals, for
`test/unit/test_unishox2_decode.py`.

- Generated by `gen_unishox2_vectors.py` in this directory, on a bench Pi.
- It uses the reference C library through `unishox2-py3` 1.0.0, the binding
  the TAK Meshtastic Gateway installs. The file records the version itself.
- The corpus is a fixed list plus 400 strings drawn with seed 20261023 from
  five character palettes: ASCII, upper case, hex, symbols and Unicode.
- Each vector is decompressed to its known length and kept only if it
  round-trips.

## `upstream_takpackets.json`

`ATAK_PLUGIN` payloads from upstream senders, for
`test/unit/test_fml_lora_gw.py`. Each entry names its source:

- **`ots_pli`:** captured on 2026-10-23 from OpenTAKServer 1.7.13's
  Meshtastic outgoing queue, for a synthetic client. Its position is synthetic.
- **`tmg_dm_mixed`:** built with the TAK Meshtastic Gateway 1.1.0's own
  `atak_pb2` and `unishox2-py3` 1.0.0, the way its direct-message path builds
  one: compressed strings except `chat.to`. As published, that path assigns a
  `str` to `chat.to`, which its `atak_pb2` types as bytes, so it raises before
  sending. This packet is what the path would send with that line fixed.
- **`tmg_pli_plain`:** built with the same `atak_pb2`, with the plain strings
  its position path sends.

To regenerate the vectors, run the generator where `unishox2-py3` is installed
and commit the output. The tests never need the library.
